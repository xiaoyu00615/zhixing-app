## 1. 产品概述

“知行｜个人知识与行动中枢”是一款单用户、本地优先、离线优先的个人效率与知识管理软件。

目标不是只做 Todo，也不是做多人协作平台，而是形成个人信息从“捕捉”到“执行、整理、检索、再次利用”的完整闭环。

核心信息流：

```text
快速捕捉
→ 梳理
→ 转为 Task / Note / Diary / Canvas
→ 执行或沉淀
→ 搜索 / 关联 / 回看
→ 再利用
```

## 2. 核心产品理念

### Capture

任何碎片信息都能先记下来，不要求用户立即决定它最终属于什么。

### Connect

Task、Note、Diary、CanvasNode、CaptureItem 等内容可以通过关系建立联系。

### Convert

CaptureItem 和部分 Document 内容可以转化或关联到 Task、Note、Diary、Canvas。

### Local First

核心功能不依赖网络、账号、云服务。网络只用于未来自己的设备之间同步等扩展能力。

### Data Ownership

用户可以查看、迁移、备份、恢复自己的本地数据位置，不被单一云服务绑定。

## 3. 核心模块

### 3.1 首页 / Today

首页只负责“看今天”和快速进入下一步。

主要内容：

- 问候与日期；
- 4 个 KPI 摘要；
- 今日重点任务；
- 今日日程；
- 最近 CaptureItem；
- 最近 Note；
- 最近 Canvas；
- 快速记录。

首页不是完整任务系统，不放完整四象限、完整月历、完整 Canvas 编辑器。

首页快速记录位于正常文档流最后一块，不是 Sticky Footer。设计图中展示条目数量只属于视觉示例，不是数据库硬限制。

### 3.2 CaptureItem / QuickCapture

`CaptureItem` 是独立轻量实体，承接“先记下来、稍后整理”的碎片内容。

可以后续：

- 转为 Task；
- 转为 Note；
- 转为 Diary；
- 添加到 Canvas；
- 与现有实体建立关联。

如保留 `@` 语义，只表示引用本地实体，不表示人员 Mention。

### 3.3 Task

一级视图：

- 列表；
- 四象限；
- 日历；
- 时间线。

核心能力：

- CRUD；
- status：todo / doing / completed / cancelled；
- Importance；
- Urgency；
- Deadline；
- Overdue 动态计算；
- Project；
- Tag；
- Task Detail Drawer；
- Create/Edit Modal；
- 软删除与恢复；
- 关联 Note / Diary / Canvas。

Project 是 Task 内部轻量分组实体，不做一级导航。

Importance 与 Urgency 分离。Overdue 可以影响 Urgency，但不自动修改 Importance。

Archive 不是 Task status。

Timeline 具体交互当前未冻结为甘特图，不因 Timeline 自动增加 `start_at`。

### 3.4 Canvas

正式产品拆成：

1. Canvas List；
2. Canvas Editor。

初始 Node Types：

- text；
- sticky；
- image；
- link；
- task；
- note；
- diary。

组织与编辑能力：

- Edge；
- Group；
- 多选；
- Copy / Paste；
- Undo / Redo；
- Zoom / Pan；
- MiniMap；
- 当前画布搜索；
- 按需 Node Property Panel。

AI 整理属于未来 Phase 8，不是 Phase 3 实现内容。

### 3.5 Diary

Diary 强调按日期记录和回看。

主要入口：

- 今天；
- 日历；
- 时间线；
- 智能日记夹 / Saved View。

Diary 使用独立逻辑日期 `diary_date`，与创建时间分离，支持补写过去日期。

智能日记夹是本地规则筛选，不是 Note Folder，不依赖 AI。

### 3.6 Note

Note 强调知识编辑、整理、关联、检索。

主要能力：

- Note List；
- Folder；
- Tag；
- Favorite；
- Tiptap 富文本编辑；
- Attachment；
- Related Content；
- Local Auto Save。

Folder 与 Tag 区分：Folder 是 Note 内部组织；Tag 是跨模块分类。

Diary 与 Note 数据层优先共用 Document，通过 type 区分，但产品页面与使用目的保持独立。

### 3.7 Global Search

Global Search 是独立本地全文搜索中心，不等于 Ctrl+K。

实体结果范围基线：

- Task；
- Canvas；
- CanvasNode；
- Note；
- Diary；
- CaptureItem。

Attachment metadata 后续可扩展。

Project 是筛选维度；Favorite 是属性 / 特殊视图，不是实体类型。

Ctrl+K 保留给 Command Palette：快速导航、快速命令、快速创建、最近访问。

### 3.8 Tag

Tag 是跨模块用户自定义标签，可服务 Task / Note / Diary / Canvas / CaptureItem 等支持实体。

Tag 不等于 Project、Folder、Badge、Status。

### 3.9 Archive

Archive 是独立数据生命周期能力，不是 Task status。

归档内容默认从主要工作页面隐藏，但可恢复。Archive 中执行 Delete 会进入 Trash，不允许从 Archive 直接物理永久删除。

### 3.10 Trash

Trash 展示 Soft Delete 内容。

支持：

- 恢复；
- Permanent Delete；
- 批量恢复；
- 清空 Trash（强确认）。

Global Search 默认排除 Trash 内容。V1 不默认自动物理清空核心数据。

### 3.11 数据与存储

支持：

- 当前数据位置查看；
- 打开所在文件夹；
- 简单模式 / 高级模式；
- 安全迁移；
- 数据位置失效恢复；
- Attachment 管理；
- Cache 清理；
- 导入 / 导出。

简单模式只让用户选择一个数据根目录；高级模式才拆分 Database / Attachments / Backup / Cache。

### 3.12 Backup / Restore

Backup 是数据安全能力，不等于 Sync。

支持：

- Manual Backup；
- Auto Backup；
- Backup History；
- Restore；
- Restore 前 Safety Snapshot；
- Staging Restore；
- Manifest / Hash / Integrity Check。

### 3.13 Device Sync

仅用于同一个用户自己的设备，例如 Windows PC <-> Android Phone。

每台设备有独立本地数据库，通过 Sync Engine 增量同步。

设备是对等 Peer，无默认主设备。IP 不是设备身份。

### 3.14 AI

AI 是嵌入式工具，不作为一级主导航。

未来可能用于：自动标签、总结、Canvas 整理、关系发现、任务提取、日期识别等。

## 5. 平台关系

### Web

与 Desktop 共用 React UI。Phase 1B 建立真实 Web Persistence：SQLite WASM + OPFS + Web Repository Adapter。

### Windows Desktop

使用 Tauri 2 包装共享前端，通过 Rust / Tauri Plugin 获得 SQLite、文件系统、通知、备份、数据迁移等系统能力。

### Android

后续使用 Tauri 2 Mobile 路径发展。Mobile UI 必须单独适配，不把 Desktop 直接等比缩小。Android UI 设计最迟在 Phase 7 正式验收前补齐。

## 6. 数据原则

- Native 核心事实来源：SQLite；
- Web 核心事实来源：浏览器本地 SQLite WASM + OPFS；
- 每个平台维护自己的本地数据；
- Repository Interface 对上层保持一致；
- Attachment 保存实际文件，数据库保存 metadata；
- 多设备绝不直接共享同一实时 SQLite 文件。
