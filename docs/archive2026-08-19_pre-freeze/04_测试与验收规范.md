# 04｜测试与验收规范

版本：V1.0  
日期：2026-08-19

## 1. 目标

测试的目的不是证明“代码看起来正确”，而是确认：
- 功能真的能运行
- 数据真的能保存
- 重启真的不会丢
- 错误真的能恢复
- UI 真的符合规范
- 新修改没有破坏旧模块

## 2. 测试层级

### Level 1｜Unit Test
负责纯逻辑，例如：
- Urgency Calculation
- Overdue Calculation
- Quadrant Calculation
- Date Helper
- Entity Validation
- Search Query Builder

主要工具：Vitest。

### Level 2｜Repository / Integration Test
负责数据层，例如：

创建 Task → 关闭连接 → 重新打开 → 查询 → 数据仍存在

检查：
- Migration
- CRUD
- Soft Delete
- Restore
- Relation
- Transaction

### Level 3｜Component / UI Test
负责组件和页面行为：
- Button
- Modal
- Drawer
- Form
- Validation
- Empty State
- Loading
- Error
- Table
- Canvas Toolbar

### Level 4｜E2E
主要工具：Playwright。

典型流程：

创建任务 → 修改 → 完成 → 刷新 → 仍然存在 → 删除 → 回收站恢复

### Level 5｜Native Smoke Test

Windows：
- 应用启动
- Tauri Command
- SQLite
- File System
- Attachment
- Shortcut
- Backup
- Notification（涉及时）

Android：
- 启动
- 本地数据
- 触控
- 返回
- 键盘
- 文件
- 局域网同步（Phase 7）

## 3. 测试状态定义

仅允许：
- PASS
- FAIL
- NOT RUN
- BLOCKED
- NOT APPLICABLE

不得在未运行时标记 PASS。

## 4. 每次开发最低测试要求

### UI-only 修改
至少：
- Type Check
- Build
- 页面运行
- 1920×1080
- 1440×900
- Hover
- Focus
- Empty / Error（适用时）

### 数据逻辑修改
至少：
- Unit Test
- Repository Test
- Migration Test
- Restart Persistence Test

### Tauri / Native 修改
至少：
- cargo test
- tauri check / build（根据阶段）
- Windows 实际运行

## 5. UI 验收

### 1920×1080
必须验证：
- Sidebar 224px 视觉正常
- Topbar 60px
- 页面不异常拉伸
- 内容区层级正确
- Card 不过度稀疏
- Drawer 不溢出
- Modal 居中
- Table 宽度合理
- Canvas 可用区域正常

### 1440×900
必须验证：
- 无横向异常滚动
- Sidebar 不压缩错误
- 顶部工具不重叠
- 卡片合理换行
- Drawer 可用
- 表格可滚动 / 自适应
- 主要操作仍可见

### 1280px Desktop
至少保证核心页面仍可操作。

## 6. 系统状态验收

### Empty
没有数据时必须有明确标题、解释和主要行动按钮。

### Loading
不得整页长期只有 “Loading...”，优先 Skeleton。

### Error
必须解释发生了什么并提供重试 / 恢复方式。

### Offline
核心本地功能继续正常工作。

## 10. Backup 验收示例

必须验证：
- 手动备份
- 自动备份
- Backup History
- Restore
- Restore 前安全快照
- 数据完整性
- Attachment Restore
- 错误 Backup 不覆盖正常数据

## 11. LAN Sync 验收示例

### Case A
PC 创建 Task A → Sync → Android 出现 Task A

### Case B
Android 修改 Task A → Sync → PC 收到修改

### Case C
断网后两端各自新增 → 恢复局域网 → 最终两端均包含全部变化

### Case D
两端同时修改同一 Entity → 必须进入 Conflict → 不得静默丢数据

### Case E
PC 删除 Task → Phone 同步 → Task 消失 → 后续不得复活

### Case F
同步中断 → 重连 → 从正确 Cursor 继续

## 12. 测试报告格式

每轮报告：

```text
测试名称：
执行命令：
执行环境：
执行时间：
结果：

失败日志：
原因：
修复：
重测结果：
```

重要 Phase 建议将测试记录保存到：

```text
docs/testing/
```

## 13. Definition of Done

一个模块只有同时满足以下条件才能 DONE：
- UI 完成
- 业务逻辑完成
- 数据层完成
- 数据重启恢复
- 错误处理
- Empty
- Loading
- Error
- 适用自动测试 PASS
- Web Build PASS
- Windows 验证 PASS（适用时）
- 响应式验证 PASS
- 用户人工审核通过

“页面能打开”不等于 DONE。
