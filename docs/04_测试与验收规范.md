# 04｜测试与验收规范

版本：V1.1  
日期：2026-08-19  
状态：CURRENT

## 1. 目标

测试不是证明“代码看起来能跑”，而是确认：

- 功能真的可执行；
- 数据真的持久化；
- 重启后不会丢；
- Error / Empty / Loading 可恢复；
- Web 与 Native 行为符合统一 Contract；
- UI 符合冻结规范；
- 新修改没有破坏已验收模块；
- 高风险数据操作不会静默丢数据。

## 2. 测试状态

只允许：

- PASS；
- FAIL；
- NOT RUN；
- BLOCKED；
- NOT APPLICABLE。

未运行不得标 PASS。

## 3. Level 1｜Unit Test

主要工具：Vitest。

适合：

- Overdue Calculation；
- Importance / Urgency / Quadrant 规则；
- Date Helper；
- Entity Validation；
- Node Content Schema；
- Search Query Builder；
- Manifest Validation；
- Conflict Decision Logic 的纯函数部分。

## 4. Level 2｜Repository / Database Integration

必须覆盖：

- Migration；
- CRUD；
- Transaction；
- Soft Delete；
- Restore；
- archived_at；
- Relation；
- FTS；
- Restart Persistence；
- Web / Native Repository Contract 一致性。

典型测试：

```text
Create
→ Commit
→ Close DB
→ Reopen
→ Query
→ Data still exists
```

## 5. Level 3｜Component / UI Test

覆盖：

- Buttons / Inputs；
- Modal / Drawer；
- Form Validation；
- Empty / Loading / Error；
- Task Row；
- Canvas Toolbar / Node Property；
- Editor Save State；
- Search Result Preview；
- Backup / Conflict 高风险确认组件。

## 6. Level 4｜Web E2E

主要工具：Playwright。

覆盖完整用户流：

```text
Create
→ Edit
→ Refresh
→ Reopen
→ Delete
→ Restore
```

Phase 1B 后必须对 Web 真实 OPFS 持久化做 E2E，不以 Memory Mock 代替主验收。

## 8. UI 验收基准

### 1920 × 1080

- Sidebar 224 px；
- Topbar 60 px；
- 主内容不异常拉伸；
- 首页 KPI 四列；
- Drawer 不溢出；
- Modal 正确居中；
- Canvas 可用区域最大化；
- Settings 二级导航与内容宽度正常。

### 1440 × 900

- 首页 KPI 仍优先四列；
- 无异常横向滚动；
- Sidebar 不压缩错误；
- 顶部工具不重叠；
- Drawer 可用；
- 主操作仍可见。

### 1280 px Desktop

核心页面仍可完成主要任务。更窄断点必须实际验证后再设计，不可由 Agent 猜测。

## 9. 系统状态验收

### Empty

有明确标题、说明、单一主要行动。

### Loading

优先 Skeleton；局部操作才用 Spinner。

### Error

必须解释问题并提供重试 / 恢复路径。

### Offline

核心本地功能继续工作。主页面不长期显示大型 Sync 状态。

### Local Save

编辑类页面至少考虑：

- 正在保存；
- 已保存到本地；
- 保存失败 / 重试。

## 15. Search / Archive / Trash 验收

### Search

- Task / Canvas / CanvasNode / Note / Diary / CaptureItem 可搜；
- 结构化筛选与 FTS 配合；
- Trash 默认不出现；
- Preview → Open Entity。

### Archive

- Archive；
- Restore；
- Delete → Trash；
- 不允许从 Archive 直接物理删除。

### Trash

- Restore；
- Permanent Delete 强确认；
- Clear Trash 强确认；
- 未确认时不自动物理清理核心数据。

## 16. Storage / Migration 验收

至少：

- 简单模式路径；
- 高级模式路径；
- 目标空间不足；
- 目标不可写；
- 数据位置突然失效；
- 不创建空数据库；
- Pause + Flush；
- Safety Snapshot；
- Temporary Target；
- Hash / `integrity_check`；
- Reopen；
- Switch；
- 旧数据未被自动删除。

需要模拟迁移中断，验证原数据仍可恢复。

## 17. Backup / Restore 验收

至少：

- Manual Backup；
- Auto Backup；
- Backup History；
- Portable Settings；
- Backup Manifest；
- 文件 Hash；
- Staging Restore；
- Restore 前 Safety Snapshot；
- Backup 损坏时拒绝切换；
- Attachment 缺失时明确失败 / 警告；
- Device-local Settings 不被跨设备 Backup 覆盖。

## 18. LAN Sync 验收

### Case A｜创建

PC 创建 Task A → Sync → Android 出现 A。

### Case B｜修改

Android 修改 A → Sync → PC 收到修改。

### Case C｜离线分叉

两端离线各自新增 → 恢复局域网 → 两端最终都有完整变化。

### Case D｜冲突

两端同时修改同一 Entity → 不得静默 Last Write Wins → 进入 Conflict。

### Case E｜删除

PC Soft Delete → Sync → Android 进入对应删除状态 → 后续不得无依据复活。

### Case F｜断点续传

同步中断 → 重连 → 从正确 Cursor 继续。

### Case G｜Attachment

不同设备本地路径不同，但通过 Attachment metadata + hash + bytes 正确传输，并由目标 StorageAdapter 决定保存位置。

### Case H｜Remove Device

撤销 Trust 后停止同步，但另一设备本地业务数据不被远程删除。

## 20. Definition of Done

一个模块只有同时满足以下条件才可 DONE：

- UI 完成；
- 业务逻辑完成；
- Repository / 数据层完成；
- 数据重启恢复；
- Error / Empty / Loading 完成；
- 适用自动测试 PASS；
- Web Build PASS；
- 适用 Native Smoke PASS；
- 响应验证 PASS；
- 用户人工审核通过。

“页面能打开”不等于 DONE。
