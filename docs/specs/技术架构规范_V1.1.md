# 1. 总体架构

```text
React UI
   ↓
Application Service
   ↓
Repository Interface
   ↓
┌──────────────────────────────┐
│ Native Adapter               │
│ Web Adapter                  │
│ Test / Memory Adapter        │
└──────────────────────────────┘
   ↓
SQLite / OPFS / File System / System API
```

核心原则：

- UI 不知道底层数据库实现；
- Native 与 Web 共用领域模型和 Repository Contract；
- 平台差异通过 Adapter / Platform Service；
- 高风险数据操作集中到专门 Service / Rust，不散落页面；
- 测试可替换 TestRepository。

# 4. 领域模型基线

**Domain entity schema ≠ Sync metadata schema。**

核心实体的**业务字段**由各 domain contract 决定：

```text
id: UUID
created_at
updated_at
deleted_at
```

需要 Archive 的实体优先评审 `archived_at nullable`。

Phase 7 **不要求**给所有业务行增加 `device_id` / `revision`：

- `device_id` 是设备级稳定标识，不是每行业务字段，也不是 cryptographic identity；
- 标量 `revision` 无法表达多设备并发，不能单独作为同步因果判据。

同步元数据可能独立存在于 `SyncChange` / `SyncState` / `Tombstone` / `Conflict` 或未来批准的数据结构；具体物理模型 **NOT FROZEN**，由 Phase 7 Sync Data Model 单独设计（本规范不在 docs-only 阶段提前设计 SQL）。

## 4.1 Task

业务字段方向：

```text

description / content
status: todo | doing | completed | cancelled
due_at
importance
urgency
project_id nullable
```

Overdue 动态计算，不存为 status。

Task 的 Importance 与 Urgency 分离；Overdue 只允许影响 Urgency 逻辑，不修改 Importance。

Subtask 模型与 Timeline 是否需要 `start_at` 在 Phase 0 决定。

## 4.2 Project

字段方向：

```text

```

# 6. Tiptap / Document 技术

Tiptap 3 作为 Diary / Note / Task Description 的富文本核心。

保存：

- `content_json` 用于完整恢复；
- `plain_text` 用于 FTS / Preview / AI。

```text

→ Dirty State
→ Save Queue / Debounce
→ DocumentService
→ Repository
→ Local Save Status
```

# 7. Native：Tauri 2 + Rust

Tauri 2 包装共享前端，Windows 与 Android 通过同一工程发展。

Tauri Capability 按最小权限配置。

React 只能访问明确授权的 Command / Plugin API。

高风险能力优先放在 Rust / Platform Service：

- 安全数据位置迁移；
- Backup / Restore；
- Hash / Integrity；
- LAN Sync；
- 文件系统权限边界。

Native SQLite CRUD 可通过 Tauri SQL Plugin / Rust 数据服务实现，但最终数据驱动方案需在 Phase 0 验证 Windows + Android 支持、Migration、Backup API 和测试便利性后冻结。不得同时建立两套互相竞争的通用 Repository 数据层。

# 8. Native SQLite

SQLite 是 Native 核心事实来源。

要求：

- Foreign Keys；
- Transaction；
- Migration；
- FTS5；
- 本机文件系统；
- 合理使用 WAL；
- 不放 NAS / SMB 作为实时主库。

Schema 变更只走 Migration，例如：

```text
001_initial.sql
002_add_project.sql
003_add_capture_item.sql
004_add_archive_fields.sql
```

禁止“启动时如果字段不存在就临时 ALTER”的散乱逻辑。

# 9. Web：SQLite WASM + OPFS

Phase 1B 必须落地真实 Web Persistence。

架构：

```text
React
→ Web Repository Adapter
→ Database Worker
→ SQLite WASM
→ OPFS
```

原则：

- DB 运算放 Worker，避免阻塞 UI；
- Web 与 Native 不是同一个 sqlite 文件；
- Repository Contract 对上层一致；
- OPFS 不可用时给明确提示 / 受限模式；
- 不静默降级到易丢失存储。

# 10. Search 技术

使用 SQLite FTS5 作为本地全文搜索核心，不引入 Elasticsearch / Meilisearch 等服务器搜索引擎。

FTS 基线：

- Task title / description；
- Canvas title；
- CanvasNode 可检索文本；
- Note title / plain_text；
- Diary title / plain_text；
- CaptureItem plain_text。

Tag / Project / Status / Date / archived_at 属于结构化 Filter，使用普通 SQL / Join / WHERE，不强塞给 FTS。

Global Search 默认排除 `deleted_at IS NOT NULL` 的 Trash 内容。

Ctrl+K Command Palette 不走完整 Global Search UX。

# 11. Attachment / File Storage

附件实际文件不作为大量 SQLite BLOB。

StorageAdapter 决定真实存储位置。

数据库只存 metadata 和设备本地 `relative_path`。

SHA-256 用于：

- 完整性验证；
- 去重辅助；
- Backup；
- Sync Missing File Detection。

不同设备不要求拥有相同 `relative_path`。

# 12. Storage 目录

简单模式建议：

```text
ZhixingData/
├─ database/
├─ attachments/
├─ thumbnails/
├─ backup/
└─ metadata/
```

高级模式允许分开设置 Database / Attachments / Backup / Cache。

Data Root Manifest 与 Backup Manifest 分离。

Data Root Manifest 描述当前数据目录结构与版本；Backup Manifest 描述某次 Backup 的文件清单、Hash、Schema / App / Format 版本。

# 13. 安全数据位置迁移

不得直接修改路径字符串，也不得依赖直接复制运行中的 sqlite / wal / shm。

基线流程：

```text
Validate Target
→ Check Space
→ Pause Writes
→ Flush Pending Writes
→ Create SQLite Safety Snapshot
→ Copy to Temporary Target
→ Verify Hash + SQLite integrity_check
→ Reopen Target
→ Verify Attachments
→ Commit Path Switch
→ Keep Old Data Until User Confirms
```

Phase 6 决定具体使用 SQLite Backup API、checkpoint、`VACUUM INTO` 或等价安全机制。

若数据位置失效，禁止自动创建空数据库。

# 14. Backup

完整 Backup 基线：

```text
Database
Attachments
Portable Settings
Backup Manifest
```

Portable Settings 与 Device-local Settings 分离。

不得从 Backup 无脑恢复：

- device_id；
- 本机绝对路径；
- Trust Token；
- Pairing Credential；
- Device Identity private key material（provider-managed identity key material）；
- 本机权限状态；
- 其他 Device-local 配置。

Device Identity 的 private material **不进入业务 SQLite、不进入 Database Backup、不进入 Portable Settings、不进入 Data Root**；**禁止**出现「完整备份 / 恢复即可把设备身份私钥复制到另一设备」的语义。

# 15. Restore

优先 Staging Restore：

```text
Select Backup
→ Validate Manifest
→ Verify Hash
→ Create Current Safety Snapshot
→ Unpack to Staging
→ Validate Database / Attachments
→ Reopen Staging Data
→ Final Verification
→ Switch to Restored Data
```

恢复失败时原正式数据必须保持可恢复。

# 16. Archive / Trash 数据生命周期

推荐评审方向：`archived_at nullable`。

```text
Normal
<-> Archive
Archive Delete → Trash
Normal Delete → Trash
Trash Restore → Previous Logical State
Trash Permanent Delete → Physical Delete
```

Permanent Delete 只从 Trash 发生。

V1 默认不执行“30 天自动物理清空”等破坏性策略。

# 17. Device Sync（Phase 7）

正式实现前只预留接口。

## 17.1 拓扑与身份

```text
Peer A Local SQLite
       <->
    Sync Engine
       <->
Peer B Local SQLite
```

每台设备独立 SQLite，不共享同一个 SQLite 文件。所有设备是对等 Peer，**没有默认主设备**。

- `device_id` = 稳定设备标识；
- `device_id` **≠** cryptographic Trust Identity；
- IP 地址 **≠** 设备身份；
- Backup / Restore **≠** Sync（Backup 是数据安全 / 历史恢复，Sync 是多设备一致性）。

## 17.2 P7-S0 已冻结的架构决定（Human Review PASS）

**FROZEN**：边界（IN / OUT of scope）、威胁原则、身份分离、同步安全不变量。

- **身份分离**：Trust Identity 属于 **Device-local state**，需要密码学身份；`private key` / `device secret` **不得**随普通 Database Backup / Restore 被恢复到另一设备。DeviceSecret（private key / pairing secret 等）与 device-local trust metadata（trusted peer public identity / fingerprint / display name / revocation status）**不要求相同物理存储**。具体 secret storage backend 的**方向**已由 **P7-S1** / **P7-S1R** 研究并冻结（见 §17.8）；本规范不选具体库、不装依赖。
- **Pairing**：Pair Code / QR = **temporary pairing material**（临时配对材料），有时效、可防重放、需要用户确认；**不是永久共享密码**。推荐方向为 SAS / human verification。
- **Remove Device = Revoke Trust**：不远程删除对方数据；本机即使 peer 离线也必须能立即撤销 Trust。
- **Change capture**：business mutation + 对应 SyncChange 必须同事务（不得出现 business committed / sync change missing）。推荐方向为 persistence-layer transaction / dual-write，具体代码结构 DEFER。
- **Change identity**：不得只依赖 `(device_id, restorable monotonic seq)`（Database Restore ⇒ sequence rewind ⇒ identity collision）；方向为 globally unique random identity（UUID-style，具体版本 DEFER）。
- **Restore × Sync**：Database Restore 可能回滚 business rows / sync journal / cursor / sequence ⇒ Phase 7 必须具备 device incarnation / sync epoch 或等价 restore-safe 机制；Restore 成功后不得盲信旧 cursor / 旧 sequence identity。Data Root Migration = same device ≠ new device。
- **因果性要求**：Sync protocol 必须能区分 causally newer / causally older / concurrent / duplicate；wall-clock only 不足。
- **Search**：Search / FTS = derived local projection，不得作为跨设备业务真值同步。
- **Maintenance**：Sync 必须复用 Phase 6 Maintenance admission / barrier；禁止第二套 DB global lock。
- **Transport**：必须为 authenticated encrypted transport（Windows + Android / mutual device authentication / MITM resistance / reconnect / batching / backpressure）；禁止 custom crypto。
- **Sync Engine 层**：Rust Native Core = RECOMMENDED ARCHITECTURE DIRECTION。
- **Web**：Web Sync 对 V1 为 OUT OF SCOPE；第一验收目标为 Windows ↔ Android。

**NOT FROZEN**（留待后续 slice）：

- exact causal model（Version Vector / Dotted Version Vector / HLC / 其他 bounded causal representation）；
- 关系并发的 exact 算法（OR-Set 仅为候选，不是 V1 强制算法）；
- crypto backend 与库选型（dependency decision 当前 **DEFER**）；
- Device Identity 的 algorithm / curve / key size / key format（P7-TD 收口后状态：**PARTIALLY FROZEN** —— V1 Windows 实现候选 = ECDSA P-256（Windows runtime 已验证）；Windows ↔ Android 跨平台最终冻结 pending P7-S3 Android runtime gate，见 §17.9）；
- shared Device Identity capability 的 exact API method names；
- trust metadata physical format（JSON / SQLite / 具体文件名 / schema 均未冻结）；
- transport implementation（Noise-family / TLS 1.3 with pinned device identity 均为候选）——**已于 P7-T0 / P7-T2 / P7-T2R / P7-T2V / P7-TD 收口：V1 = TCP + TLS 1.3，Noise NOT SELECTED FOR V1，见 §17.9**；
- 全部物理表结构（SyncChange / SyncState / Cursor / Tombstone / Conflict）。

## 17.3 核心同步概念

- Device；
- SyncChange；
- Revision / causal metadata；
- Cursor（不得只是 `last_seen_timestamp`）；
- Ack（只有变化被持久化并成功 apply 后才能视为 applied）；
- Idempotency（同一 SyncChange 重复收到不得重复产生业务副作用）；
- Tombstone（≠ business soft delete；用于传播 hard-deleted relationship / 未来物理删除）；
- Conflict；
- Attachment Hash。

## 17.4 不参与同步（NOT SYNCED）

search / FTS projection、`schema_migrations`、backup bundles、restore operation journal、data-root-migration journal、`bootstrap.json`、private trust secrets、device-local paths / settings。

## 17.5 冲突

不可安全自动合并的内容进入 Conflict，**不默认静默 Last Write Wins**；`updatedAtMs` 较新不得自动取胜（clock drift / offline / concurrent writes）。保留双方 → 持久 Conflict → 用户解决。Note / Diary 正文 V1 不得静默覆盖。

Archive / Trash / archive-state / soft-delete / restore-state 属于业务 lifecycle，需要同步；但 ArchivePage / TrashPage 只是 projection / UI，不是 sync entity。

## 17.6 Presence 与 Attachment

不使用社交 Presence 设计；只保留产品级设备状态（可连接 / 不可连接 / 正在同步 / 同步完成 / 需要处理）。

Attachment Sync：metadata + hash + bytes；目标设备通过 StorageAdapter 决定本地路径，**不得同步另一设备的实际 local path**。Attachment Sync implementation 当前 **BLOCKED**（无共享 File Asset contract / 无 production writer / 无 hash ownership），但**不阻塞** Phase 7 核心架构。

## 17.7 网络与 Phase 边界

网络实现方向已经 P7-T0 / P7-T2 / P7-T2R / P7-T2V / P7-TD 研究并收口：**V1 = TCP + TLS 1.3 + mutual device authentication**（FROZEN architecture direction，详见 §17.9）；不在 Phase 1–6 提前侵入业务页面。

LAN Sync 正式实现只属于 Phase 7；Phase 1–6 最多做接口与数据结构预留。

## 17.8 Device Identity 存储方向（P7-S1 / P7-S1R 已冻结方向）

`device_id` 只是稳定设备标识，**不是** cryptographic identity。Cryptographic Device Identity 必须由 **operation-oriented** capability 提供。Windows 可以采用 provider-managed identity keys；共享 Device Identity capability **不得要求私钥以 raw bytes 导出**。

**共享 capability（`DeviceIdentityProvider` 或等价命名，方向冻结）**围绕以下能力设计（P7-TD 收口后）：

```text
ensure identity
status / readiness
public identity
sign
explicit reset / rotation
```

其中 `sign`：**REQUIRED BY FROZEN V1 TLS AUTH ARCHITECTURE**（§17.9）；早期版本列出的 `key agreement where required` 已于 P7-TD 移出 V1 方向——TLS 1.3 会话建立使用 ephemeral key exchange，稳定 Device Identity 是 authentication identity 而非 session-key container，故 long-lived `agree()` 对 V1 **NOT REQUIRED**（未来其他 transport 可重新评审）。方法名 / Rust trait signature **NOT FROZEN**；**禁止**把 `getPrivateKeyBytes()` 或任何等价的「导出私钥字节」入口写进 shared contract。

**Device Secret wording**：不使用「Device Secret = 32-byte seed」「generate 32 bytes」这类表述；改为 **provider-managed identity key material**。algorithm / curve / key size / key format 全部 **NOT FROZEN**。

**Windows（Preferred / Fallback / fail closed）**：

```text
Preferred: Microsoft Platform Crypto Provider      （TPM-backed）
Fallback : Microsoft Software Key Storage Provider （CNG key isolation）
If both unavailable: Sync identity = UNAVAILABLE，fail closed
```

TPM 是 **PREFERRED，不是 REQUIRED**；必须做 **runtime capability detection**，不得假定每台 Windows 机器都有可用 TPM。无可用 TPM 时回退 Software KSP；**不得** silent fallback 到 raw-byte credential storage，也**不得** silent key regeneration。Software KSP 的安全等级为 software isolation，**低于** TPM-backed hardware isolation；其要求为 CNG key isolation、provider-managed long-lived key、operation-oriented、private-key export disabled by policy。

**Windows 凭据存储术语（必须严格区分）**：

- WinRT Credential Locker / PasswordVault：可随 Microsoft Account 跨设备 roaming ⇒ **NOT SELECTED** 用于 Device Identity private key；
- Win32 Credential Manager（`CRED_PERSIST_LOCAL_MACHINE`）：same user / same computer / subsequent logon sessions，**不**在该用户的其他计算机上可见 ⇒ 仅 raw-byte fallback candidate；
- Win32 Credential Manager（`CRED_PERSIST_ENTERPRISE`）：may roam across computers ⇒ 不作为 default。

不得把 `CRED_PERSIST_LOCAL_MACHINE` 写成「visible to other Windows users」。Credential Manager 的最终定位是 **raw-byte fallback candidate only，不是 preferred identity backend**。

**DPAPI**：仅 current-user 作用域，**DEFER**；禁止 `CRYPTPROTECT_LOCAL_MACHINE` 作为默认 Device Identity 秘密方案，因为其 raw private material 会进入应用内存，达不到 CNG operation-oriented 的安全等级。

**Android**：Android Keystore 为 operation-oriented；方向 **FROZEN**，implementation **DEFER**。private key material 不得通过 shared contract 导出。硬件保护在可用时 preferred。StrongBox 为 **OPTIONAL，非 required**。

**StrongBox wording**：必须区分 Android Keystore / KeyMint capability、TEE-backed capability、StrongBox hardware subset 三层；StrongBox 的具体算法集合只是 **StrongBox backend subset**，**不是** Android 全局算法限制。不得写「Android only supports P-256」，也不得写「StrongBox = Android Keystore 全部能力」。

**Cross-platform algorithm**：P7-TD 收口后状态为 **PARTIALLY FROZEN**：V1 Windows 实现候选 = **ECDSA P-256**（Windows CNG runtime 已由 P7-S2 / P7-T2V 真机验证）；Windows ↔ Android 跨平台最终冻结 **pending P7-S3 Android runtime gate**。P7-T2V 使用 P-256 属 **VALIDATION PARAMETER**，不是永久算法锁。Curve25519 / X25519 必须如实记录：Windows CNG 存在 documented named-curve capability、Android 13 KeyMint v2 已 document Curve25519，但 Zhixing production suitability **NOT VALIDATED**、StrongBox 不保证；**不得**写「Ed25519/X25519 BLOCKED」或「Android Keystore has no X25519」。详见 §17.9。

**Trust metadata**：

```text
location  : app_config_dir    （FROZEN）
lifecycle : device-local      （FROZEN）
Database Restore    : 不得回滚它
Data Root Migration : 不得移动它
physical format     : DEFER（不冻结 JSON / SQLite / 具体文件名 / schema）
```

**Crypto Identity vs Sync Epoch**：二者正式区分。Database Restore 时 crypto identity **unchanged**、sync epoch **rotates**，且 stale journal / cursor **不得盲信**；Data Root Migration 时 crypto identity **unchanged**、sync epoch **unchanged**。

**Secret loss**：`device_id` 存在但 identity secret / key 不可用时，结果为 **Sync unavailable / fail closed**、保留 trust 证据、**NO silent regeneration**；必须由用户显式 repair 或 reset identity / re-pair。首次启动逻辑为 `ensureDeviceIdentity()`（内部按 provider 选择 open persisted identity 或 create provider-managed identity），具体算法 **DEFER**。

**Reinstall / uninstall 语义**：Windows CNG、Windows Credential Manager、Android Keystore 三者当前均为 **NOT VERIFIED**；平台官方资料未证明的部分不得用推断代替事实。

**Dependency decision**：**DEFER**。`keyring-core` / `windows-native-keyring-store` 与 `rust-version >= 1.88` 均**不再视为已批准**（`rust-version` 维持 `1.77`；本地 rustc 较新不构成提升项目 MSRV 的授权）。已记录只读事实：现有 `windows-sys 0.61.x` 可通过追加 feature 暴露所需 Windows API families，但 **feature 变更仍属于 `Cargo.toml` 的 code / dependency-contract 变更**，未经授权不得执行。

**CNG implementation gates（属实现门，不是当前架构 blocker）**：

```text
Gate A：private export 被禁用时，public key blob 是否仍按预期导出
Gate B：无 TPM 环境下 Platform Crypto Provider 的真实失败行为 / error
```

P7-S2 / P7-S2R2 真机实测后：**Gate A = PASS**（RUNTIME FACT，含正向对照）；Gate B 本机有 TPM 2.0 **未实测**，仅由文档化 `TBS_E_TPM_NOT_FOUND` + 纯选路逻辑证明，不得声称已真机验证。

**Stronghold**：V1 **NOT SELECTED**。它是 encrypted vault，与 root-of-trust / unlock-secret bootstrap **不是同一层**；它本身**不能解决** vault 解锁根秘密的来源问题——这不等于「没有安全价值」。

## 17.9 P7-TD 综合冻结：设备身份 / 配对 / Transport（P7-S2C–P7-T2V 收口）

本节是 P7-S2C / S2CR、P7-T0 / T0R、P7-T1 / T1R、P7-T2 / T2R / T2V 研究与验证的统一文档收口（P7-TD，DOCS-ONLY CONSOLIDATED FREEZE）。结论按冻结级别标注：**FROZEN** / **IMPLEMENTATION GATE** / **RECOMMENDED** / **DEFER** / **RUNTIME FACT**（真机实测事实）。

### 17.9.1 设备身份基本不变量（FROZEN）

- `device_id` **≠** cryptographic Device Identity；Device Identity = **stable authentication identity**。IP、hostname、display name 均不得当作安全身份。
- Device Identity private material：**device-local**；平台支持处 **provider-managed**；**不得**通过 shared API 暴露私钥材料；**不随普通 Backup portable**、**不随 Data Root Migration portable**。
- 秘密丢失 ⇒ **fail closed**；**NO silent regeneration**；必须显式 reset / repair / re-pair。

### 17.9.2 Windows 设备身份：方向（FROZEN）与已验证事实（RUNTIME FACT）

方向（与 §17.8 一致）：Preferred = Microsoft Platform Crypto Provider（TPM-backed）；Fallback = Microsoft Software KSP；TPM Available 但 Platform Provider 失败 ⇒ **FAIL CLOSED**（禁止静默回落 Software）；TPM NotFound ⇒ 允许 Software KSP；禁止 raw-byte silent fallback。

P7-S2 / P7-S2R2 真机 RUNTIME FACT：Platform Provider 可用、TPM 2.0、hardware-backed flag 实测；「private export disabled + public export 成功」validated；private export denied validated；handle cleanup validated；presence proof fail-closed（三态）。

P7-T2V 真机 RUNTIME FACT（STRONG PASS / VALIDATION CLOSED）：provider-managed、不可导出的 P-256 测试键（`zhixing-test-*` 命名空间）经 rustls `SigningKey` / `Signer` 包装完成**真实 TLS 1.3 握手**（`ECDSA_NISTP256_SHA256`），对端真实验签（无 skip 路径），负向测试（篡改签名 / 错误公钥）正确失败。签名路径 = unhashed TLS message → SHA-256 一次 → `NCryptSignHash` → **64B IEEE-P1363（r‖s）→ DER ECDSA-Sig-Value** 转换 validated；私钥字节全程未导出；测试键零残留。该 P1363→DER 证据级别 = **RUNTIME FACT + rustls-cng 参考实现一致性**；**不得**表述为「Microsoft NCrypt 规范保证所有 ECC 输出为 P1363」（无官方规范性来源支持）。

### 17.9.3 共享 capability（FROZEN）

`DeviceIdentityProvider` 是 **platform-neutral** 契约；shared semantics 不得包含 `PlatformCng` / `SoftwareCng` / Win32 类型 / Android implementation 名称。V1 方向操作集（P7-TD 收口）= ensure identity、status / readiness、public identity、**sign**（REQUIRED BY FROZEN V1 TLS AUTH ARCHITECTURE）、explicit reset / rotation；long-lived `agree()` 对 V1 **NOT REQUIRED**（TLS 1.3 会话建立使用 ephemeral key exchange；稳定 Device Identity 是 authentication identity，不是 session-key container；未来其他 transport 可重新评审）。exact method name / Rust trait signature **DEFER**（不得在 P7-T2V 通过与文档冻结之外提前进入 production contract）。

### 17.9.4 密钥分离（FROZEN）

一把 long-lived key 默认**不得**同时承担 SIGN 与 key agreement。稳定认证私钥 = authentication / signature role；TLS ephemeral 会话密钥材料**分离**。

### 17.9.5 算法状态（PARTIALLY FROZEN）

V1 Windows 实现候选 = **ECDSA P-256**（Windows runtime validated）；Windows ↔ Android 跨平台最终冻结 **pending P7-S3 Android runtime gate**。P7-T2V 使用 P-256 属 **VALIDATION PARAMETER**，不是永久算法锁；不得写「P-256 permanently frozen」。Curve25519 记录见 §17.8（Windows CNG documented named-curve capability、Android 13 KeyMint v2 Curve25519 documented、Zhixing production suitability NOT VALIDATED、StrongBox 不保证）。

### 17.9.6 Transport（FROZEN architecture direction + RUNTIME FACT）

- **V1 carrier = TCP**（FROZEN）。QUIC **DEFER**（理由：V1 复杂度、当前需求、runtime / dependency 成本）；不得把 QUIC 写成「Noise 替代品」。
- **V1 secure handshake = TLS 1.3**（FROZEN；基于 RFC 9846 家族），要求 mutual device authentication、加密、forward secrecy。
- **Noise**：**NOT rejected as insecure**，但 **NOT SELECTED FOR V1**。原因是当前 Rust 1.77 实现可行性（snow 0.9.6 的 ToB audit / remediation provenance 未能充分建立），**不是**协议层安全否定。
- 库方向：**rustls 0.23 family = RECOMMENDED / VALIDATED DIRECTION**（1.77 software probe PASS + P7-T2V 硬件签名集成真机 PASS）；exact dependency version **DEFER UNTIL IMPLEMENTATION SLICE**。
- **crypto provider 职责分离**（FROZEN conceptual split）：rustls / TLS crypto provider 负责 session crypto、verification、ephemeral TLS crypto；platform Device Identity provider 负责 long-lived authentication private-key signing。**不得**让 ring 持有 Device Identity 私钥。ring = validated scratch TLS core crypto candidate；production crypto-provider dependency **DEFER**。
- **rustls-cng** = REFERENCE IMPLEMENTATION（P7-T2V 架构路径一致：unhashed TLS message → SHA-256 → NCryptSignHash → P1363 → DER → rustls Signer）；其 dependency selection **NOT FROZEN**，不得因参考实现存在而自动添加 crate。
- **RFC 7250 RPK**：P7-T2V 真机 validated（server RPK PASS / mutual RPK PASS / wrong pin REJECTED）⇒ RPK = **FROZEN transport credential carrier direction**。
- **Device Identity vs transport credential**：FROZEN 不变量 = 若 transport 认证凭据 ≠ 稳定 Device Identity，则必须存在 authenticated binding。V1 采用「identity key 直接作为 RPK 凭据」还是「独立 transport credential + 身份绑定」**DEFER**（P7-T2V 证明两者都可用 provider-managed signer 架构，但不裁决对象模型问题）。binding object（certificate schema / signed binding object schema / credential-generation 物理格式）**DEFER** 到 production identity implementation slice。

### 17.9.7 连接生命周期与 TLS 特性（FROZEN / DEFER）

- **C1**（FROZEN V1 direction）：专用配对 TLS 连接 → trust commit → close → 新建 paired-sync TLS 连接。理由：清晰安全边界、更简单的 channel-binding 生命周期、更简单的 revocation 推理。C2（配对后同连接继续 sync）= **NOT SELECTED FOR V1**；**不得**写「RFC 9266 证明 C2 非法」。
- **tls-exporter**（RFC 9266）：strong channel-binding candidate（RECOMMENDED）；exact pairing / SAS 派生 **DEFER**；它本身不定义 Device Identity 语义。
- **0-RTT**：V1 **DISABLED**（FROZEN）；不得用于 mutation / trust / pairing 操作。
- **Resumption**：V1 初始 **DISABLED**；未来启用必须 re-check 当前 Trust Store、绝不绕过 REVOKED。
- **Protocol version binding**（FROZEN requirement）：安全连接必须绑定 Zhixing 协议族 / 版本；TLS 候选机制 = ALPN + application transcript / domain separation；exact ALPN string **DEFER**。
- **Async runtime**：**DEFER**（repo 当前无 async runtime；不得因 rustls 存在而冻结 Tokio）。

### 17.9.8 配对与信任（FROZEN / DEFER）

- **首次配对**（FROZEN）：first contact 要求 authenticated out-of-band trust bootstrap；仅加密不足；Discovery ≠ trust。
- **Pair Code / QR**（FROZEN principle 级）：temporary、fresh、anti-replay、user-authorized、**不是**永久共享密码。**SAS** = RECOMMENDED V1 UX candidate，**NOT security-mandatory**；「6-digit」**NOT FROZEN**；exact entropy / commitment / encoding **DEFER**。
- **QR 平台事实**：官方 Tauri barcode-scanner 提供 Android / iOS 扫描；Windows 扫描不由该官方插件提供；「Windows 显示 QR + Android 扫描」在架构上可行。
- **Trust commit**（FROZEN）：UNTRUSTED → authenticated OOB → credential binding validation（如适用）→ user authorization → **atomic** TRUSTED commit；不存在 half-trusted peer。
- **Trust Store**（FROZEN）：per-peer、device-local 的 security state；不是业务 SyncChange；不随普通 Backup portable；不随 Data Root Migration portable。概念状态最小集 = UNTRUSTED / TRUSTED / REVOKED；`PAIRING` 是 process state 而非持久 TRUSTED state；物理持久化格式 **DEFER**。
- **Revocation**（FROZEN）：Remove Device = local trust revocation；效果 = 后续连接拒绝、现存 live session 失效 / 关闭、resumption state 失效、cached transport credentials 不再充分、sync resume 不得绕过 trust；不远程删除对端数据。
- **Identity change**（FROZEN）：trusted peer 稳定身份变化 ⇒ fail closed ⇒ 显式 re-pair；无 auto-replace。
- **Transport credential rotation**（FROZEN principle）：稳定身份不变且存在 authenticated continuity proof ⇒ trust 可保留；无 proof ⇒ re-pair；exact proof format **DEFER**。
- **Device identity rotation**：V1 = 身份变化 ⇒ 显式 re-pair；automated continuity **DEFER**。

### 17.9.9 应用层边界（FROZEN / DEFER）

- **Sync protocol separation**（FROZEN）：SyncChange / Ack / Resume / Conflict 不得直接依赖 rustls structs、TLS certificate structs、RPK resolver types；Transport 保持 adapter / boundary。
- **Application framing**：TCP + TLS 仍只是 byte stream ⇒ application message framing 为 **REQUIRED**（FROZEN requirement）；V1 direction = length-prefixed frames（RECOMMENDED）；exact serialization（CBOR / MessagePack / Protobuf / custom binary）**DEFER**。

### 17.9.10 Android 与跨平台状态

Android Keystore 方向（FROZEN）：operation-oriented、provider-managed、私钥材料不经 shared API 导出。**Implementation status = P7-S3 ANDROID BRING-UP REQUIRED**（IMPLEMENTATION GATE）：Android provider-managed TLS signer **NOT RUNTIME VALIDATED**；Android RPK mutual auth **NOT RUNTIME VALIDATED**。**不得**声称 Phase 7 跨平台 transport 已完成。P7-S3 必须至少 validate：P-256 signing、provider-managed private key、public identity export、rustls external signer bridge、TLS signature encoding / interoperability、（若生产选 RPK）RPK。
