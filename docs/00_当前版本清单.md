## 8. 关键冻结决策摘要

当前已经冻结并写回规范的关键决策包括：

- Project 为 Task 内部实体，不是一级导航；
- CaptureItem / QuickCapture 为独立轻量实体；
- Task status = todo / doing / completed / cancelled；
- Importance 与 Urgency 分离；Overdue 动态计算；
- Archive 不是 status，优先 `archived_at nullable`；
- Diary 使用独立 `diary_date`；
- Document 与 Tag / Attachment 使用关联关系，不使用 ID 数组字段；
- Canvas Node V1 包含 sticky；Frame 不属于 V1；
- Linked Entity 软删除不级联删除 CanvasNode；
- Ctrl+K = Command Palette；Global Search 独立；
- Trash 默认排除出 Global Search；Permanent Delete 只能从 Trash；
- Phase 1 拆为 1A Native + 1B Web Persistence；
- Storage 有简单模式与高级模式；
- Migration / Restore 使用安全快照与 Staging 思路；
- Settings 分 Portable 与 Device-local；
- Device Sync 为 Peer-to-Peer 自有设备同步，无主设备；
- Conflict 不使用静默 Last Write Wins；
- Attachment Sync 不同步跨设备实际路径。

## 9. Task V1 Contract 与 Phase 1B Reconciliation

Task V1 Contract：APPROVED / READY，限定为 `Task Core Slice 1`。

首批字段：

- `id`；
- `title`；
- `status`；
- `created_at_ms`；
- `updated_at_ms`。

Task status 固定为 `todo / doing / completed / cancelled`。首批 use cases 为 Create Task、List Tasks、Rename Task、Change Task Status；Change Status 包含 start、complete、cancel、reopen。

首批明确不包含 description、`due_at`、importance、urgency、Project、Tag、Delete / Restore、四象限、Calendar、Timeline、Search、Attachment 或 Task Detail Drawer。上述 future items 不得作为 nullable placeholder 提前进入第一张业务表。

Phase 1B：NOT COMPLETED。当前状态为 RECONCILED / READY FOR IMPLEMENTATION PLANNING。

Phase 1B 当前目标已收敛为：基于真实 `TaskRepository` contract 建立跨平台 persistence enablement。后续经独立计划与批准后，范围方向包括 Native Task persistence reference implementation、Dedicated Web Worker、官方 SQLite WASM、OPFS、`WebTaskRepository`、Native / Web contract parity 和 browser persistence verification。以上均为已批准方向，不是当前已实现能力。

为建立 Phase 1B 的真实 persistence contract，允许先冻结 Task domain / persistence contract，并建立必要的 Native reference persistence slice；这不表示 Phase 2 Application Service、Task 产品 UI 或业务交互已经开始。

正式进入 Phase 2 必须同时满足：

- Phase 1B COMPLETE；
- Task V1 contract approved；
- Native / Web persistence verified。
